# ZeroPhish — P1 Failure Modes & Degradation Matrix

**Date:** 2026-09-15  
**Version:** 2.0.0-p1  
**Scope:** Core Gateway, ML Inference, Relational Storage, Speed Layer, Streaming, Webhooks  

---

## 1. Failure Modes & Controlled Degradation Table

| Failure Scenario | Component | Trigger | Immediate System Reaction | User / Client Impact | Degradation State | Recovery Mechanism | Verification Test |
|---|---|---|---|---|---|---|---|
| **Database Transaction Failure** | SQL Repositories (`sql_repositories.py`) | DB disk full, unique constraint violation, connection lost during commit | `session.rollback()` invoked immediately in `except` block; error logged | HTTP 500 error returned; no partial or corrupt state saved | Fail-closed for affected transaction; other sessions unaffected | Connection re-acquired from pool on next request | `test_user_repository_rollback_on_error`, `test_incident_repository_rollback_on_error` |
| **Redis Cache Down / Connection Refused** | Cache Speed Layer (`factory.py`) | Redis container stopped, firewall block, network partition | `_RedisCache` catches Redis exception; delegates get/set/del to in-memory fallback | Zero user-visible error; slight cache warm-up delay on restart | Graceful degradation to process-local cache | Automatic reconnection attempted on each operation | `test_redis_cache_fallback_on_client_error` |
| **Tier 3 Gemini API Outage / High Latency** | AI Analysis Engine (`tier_3/main.py`, `circuit_breaker.py`) | Gemini API returns 503, 429, or exceeds 7s timeout | Circuit breaker records failure; after threshold (5), transitions to OPEN state | Scan response completed with T1+T2 score and "TIER3_UNAVAILABLE" fallback; critical findings preserved | Controlled degradation: partial score served with indicator | Half-open probe after 30s resets circuit upon first successful response | `test_circuit_breaker_state_machine` |
| **DistilBERT Inference Failure** | Tier 2 Heuristics (`tier_2.py`) | Torch out-of-memory or model load exception | Falls back to regex pattern matchers and domain heuristics | Scan completes with rule-based scoring; ML confidence omitted | Degraded scoring without ML weight contribution | Next inference request re-attempts model pipeline | `test_p0_remediation.py` |
| **Webhook Destination Down / Slow** | Webhook Dispatcher (`webhooks/service.py`, `gateway.py`) | External webhook receiver unreachable or taking > 10s | Webhook fired in detached background task; retry with exponential backoff; scan finalization unaffected | Zero impact to scan latency or dashboard updates | Asynchronous background retry; delivery marked `failed` in audit log | Exponential retry up to 3 times with jitter | `test_finalize_tier3_non_blocking_on_webhook_failure` |
| **Slow or Disconnected SSE Client** | Live Dashboard Stream (`gateway.py`) | Client pauses event consumption or buffer fills (> 50 items) | `_publish_to_subscriber` drops oldest events; if overflow persists (> 5), evicts subscriber queue | Client misses transient events; server event loop and memory protected | Graceful eviction of lagging subscriber | Client reconnects with fresh SSE stream and requests latest state | `test_sse_backpressure_and_subscriber_eviction` |
| **Oversized / Malformed Request Payload** | Security Middleware (`middleware.py`) | Request body > 1MB or malformed JSON | `RequestSizeLimitMiddleware` intercepts before body parse; returns HTTP 413 | Request rejected immediately | Fail-closed rejection | Client must send conforming payload | `test_upload_size_guard_rejects_oversized` |
| **SSRF Probe via Link / Webhook URL** | SSRF Validator (`security/middleware.py`) | Submission contains private IP (127.0.0.1, 169.254.169.254, RFC1918) | DNS resolved pre-connection; non-routable IP blocked before HTTP request | Scan flags link as malicious; webhook registration returns 400 Bad Request | Proactive threat containment | Normal operation resumed for valid public URLs | `test_ssrf_blackbox.py`, `test_gateway_security.py` |
| **Graceful Application Shutdown** | Gateway Lifespan (`gateway.py`) | SIGTERM, SIGINT, or container stop command | `lifespan` context manager drains pending background tasks (5s timeout), closes HTTP/Redis clients, clears SSE queues | Active requests finish cleanly; new connections refused | Orderly draining | Container orchestrator replaces instance | `test_lifespan_graceful_shutdown_drains_tasks` |
